# 宿題提出管理アプリ — ステップ1「生徒名簿 + QR発行・印刷」設計書

作成日: 2026-08-23

## 1. 背景とスコープ

小学5年1クラス（34人）の担任1名が、朝の会の前に宿題の提出をQRコードでチェックするアプリ。全体仕様は6ステップに分かれており、**本設計書はステップ1「生徒名簿 + QR発行・印刷機能」のみ**を対象とする。

ステップ1の完了条件は、**先生がラミネート用のQRカードシートを印刷できる状態**になること。スキャン機能はステップ3で扱う。

### スコープ外（後続ステップ）
- 提出物マスタ・締切設定（ステップ2）
- QRスキャン・複数選択モード（ステップ3）
- 未提出者一覧・履歴集計・自動未提出確定（ステップ4）
- JSON/CSVエクスポート・インポート（ステップ5）
- Service Worker・manifest.json によるPWA化（ステップ6）

ただしデータモデルは年度アーカイブを見据えた形で最初から定義する（後からの移行を避けるため）。

## 2. 技術スタック

| 領域 | 選定 | 理由 |
|---|---|---|
| フレームワーク | React 19 + Vite + TypeScript | 画面数が今後増えるため型安全性を優先 |
| ルーティング | react-router | 後続ステップで画面が5つ増える前提 |
| スタイリング | Tailwind CSS | 印刷用CSSを含めて記述量を抑える |
| データ永続化 | IndexedDB（`idb` ラッパー） | オフライン完結・端末内保存 |
| QR生成 | `qrcode` パッケージ | オフライン動作、SVG出力可 |
| フォント | `@fontsource/*` でセルフホスト | CDN依存を排除しオフライン要件を最初から満たす |
| テスト | Vitest + React Testing Library + `fake-indexeddb` | データ層とコンポーネントの単体テスト |

**PDF生成は行わない。** 印刷はブラウザの印刷機能（`@media print`）に委ねる。

## 3. データモデル

IndexedDB データベース名 `homework-tracker`、バージョン 1。

### 3.1 `cohorts`（年度＋クラス）

```ts
type Cohort = {
  id: string;          // uuid
  year: number;        // 年度（例: 2026）
  className: string;   // クラス名（例: "5年1組"）
  isActive: boolean;   // 現在使用中か
  createdAt: number;   // epoch ms
};
```

- keyPath: `id`
- インデックス: `by-year`（`year`）
- **`isActive: true` は常に1件のみ。** 年度更新（ステップ4以降）で新cohortを作る際に旧cohortを`false`にする。

### 3.2 `students`（生徒）

```ts
type Student = {
  id: string;              // uuid — QRに埋め込む不変の内部ID
  cohortId: string;
  attendanceNumber: number; // 出席番号
  name: string;            // 氏名（任意。未入力なら空文字）
  status: "active" | "transferredOut";
  createdAt: number;
};
```

- keyPath: `id`
- インデックス: `by-cohort`（`cohortId`）、`by-cohort-number`（`[cohortId, attendanceNumber]`、**unique**）

**出席番号の一意性は `status` に関わらずcohort内で保証する。** 転出した生徒の番号を他の生徒が再利用できると、印刷済みのQRカードと名簿がずれるため。

### 3.3 `settings`

```ts
type Setting = { key: string; value: unknown };
```

- keyPath: `key`
- ステップ1で使うキー:
  - `showStudentNames`（`boolean`、初期値 `false`）— 氏名を表示するか
  - `rosterHintDismissed`（`boolean`、初期値 `false`）— 名簿画面の初回案内を表示済みか

### 3.4 QRコードのペイロード

`hw1:<student.id>` 形式の文字列（例: `hw1:9f2c1a84-...`）。

- **接頭辞 `hw1:` は必須。** ステップ3のスキャナが無関係なQRコード（商品バーコード等）を確実に弾くため。`1` はペイロード形式のバージョン。
- 埋め込むのは内部IDであり出席番号ではない。出席番号を後から修正してもQRの再印刷が不要になる。
- 誤り訂正レベルは **Q（25%）** を使う。ラミネートしたカードは反射・傷・指紋で読み取り率が落ちるため、Mでは不足する。

## 4. 画面仕様

ルート構成:

| パス | 画面 |
|---|---|
| `/setup` | 初回セットアップ |
| `/roster` | 生徒名簿（主画面） |
| `/roster/new` | 生徒を追加 |
| `/roster/:id/edit` | 生徒を編集 |
| `/print` | QRカード印刷 |
| `/settings` | 設定 |

`isActive` なcohortが存在しない場合、どのパスにアクセスしても `/setup` にリダイレクトする。

### 4.1 初回セットアップ `/setup`

年度とクラス名を入力してcohortを作成する。

- **年度**: 数値入力。初期値は日本の学校年度に合わせて算出する（1〜3月なら前年、4〜12月なら当年）。
- **クラス名**: 自由入力テキスト。プレースホルダ `5年1組`。空文字は不可。

作成後 `/roster` へ遷移。

### 4.2 生徒名簿 `/roster` — 主画面

出席番号のグリッド。34人が1画面に収まることを設計目標とする（スマホ4列 / タブレット8列）。転入で人数が増えた場合はグリッドが下に伸び、通常どおりスクロールする。

セルの状態は3種類:

| 状態 | 表示 |
|---|---|
| 在籍 | 藍の枠線＋墨の番号 |
| 転出（欠番） | 方眼色の破線枠＋方眼色の番号、背景に薄いハッチ |
| （設定ON時）氏名 | 番号の下に小さく併記 |

- ヘッダーに `2026年度 5年1組` と `在籍33人・欠番1`
- セルをタップすると `/roster/:id/edit`
- 下部に `生徒を追加` と `QRを印刷` のボタン
- 生徒が0人のときは、グリッドの代わりに「まず出席番号を追加してください」と追加ボタンを表示する
- 初回訪問時のみ、グリッド上部に操作の案内を1行表示し、生徒を1人追加した後は表示しない（`settings` に既読フラグを持つ）

### 4.3 生徒を追加 `/roster/new`

- **出席番号**: cohort内の最大`attendanceNumber` + 1 を初期値として自動採番（転出者の番号も最大値の算出に含める）。手動で変更可能。
- **氏名**: `showStudentNames` が `true` のときのみ入力欄を表示。
- 保存後 `/roster` へ戻る。連続追加できるよう「保存して続けて追加」も用意する。

### 4.4 生徒を編集 `/roster/:id/edit`

- 出席番号・氏名を変更できる。
- **転出**: `status` を `transferredOut` に変更する。番号は欠番として維持される。確認ダイアログを表示。
- **完全に削除**: レコードを物理削除する。番号は再利用可能になる。誤操作防止のため確認ダイアログで「この生徒の記録は元に戻せません」と明示する。転出との違いを画面上で説明する。
- 転出済みの生徒には「在籍に戻す」を表示する。

### 4.5 QRカード印刷 `/print`

在籍中（`status: "active"`）の生徒のQRカードをA4に並べる。転出者は含めない。

**カード寸法**: 55mm × 60mm

```
┌╌╌╌╌╌╌╌╌╌┐  ← 裁ち線（0.2mm 方眼色の破線）
┊ ┌─────┐ ┊
┊ │ QR  │ ┊  QR 38mm × 38mm（誤り訂正Q）
┊ │38mm │ ┊
┊ └─────┘ ┊
┊    12    ┊  出席番号 20pt BIZ UDGothic Bold
┊  やまだ  ┊  氏名 9pt（設定ONのときのみ）
└╌╌╌╌╌╌╌╌╌┘
```

**シート配置**: A4縦、余白10mm、3列 × 4行 = 12枚/ページ。34人なら3ページ。カード間の余白は横12.5mm・縦12.3mm（A4の印字領域190×277mmから算出）。各ページ上部に `2026年度 5年1組` を小さく印字する（複数クラス分を刷ったときの取り違え防止）。

**印刷CSS**:
```css
@page { size: A4 portrait; margin: 10mm; }
.card { break-inside: avoid; }
```
画面上ではA4プレビューを表示し、`印刷` ボタンで `window.print()` を呼ぶ。印刷時はヘッダー・ナビゲーションを非表示にする。

### 4.6 設定 `/settings`

ステップ1では **氏名を表示する** のトグル（`showStudentNames`）のみ。OFFのとき、名簿・印刷シートの両方から氏名が消える（データは保持される）。

## 5. 視覚デザイン

### 5.1 配色

| 名前 | 値 | 用途 |
|---|---|---|
| 画用紙 | `#FBFAF7` | 地 |
| 墨 | `#1A1A1F` | 文字 |
| 藍 | `#22406B` | 見出し・枠線・構造 |
| 方眼 | `#C9D6E4` | 罫線・欠番のハッチ・裁ち線 |
| 朱 | `#D8452E` | 破壊的操作の確認と、後続ステップの花丸・締切超過**のみ** |

**朱の使用は厳格に制限する。** 先生の朱ペンが意味を持つのは、そこにしか入らないからである。ステップ1で朱が現れるのは削除確認ダイアログのみ。

コントラスト: 朱 `#D8452E` と画用紙 `#FBFAF7` の比は約4.3:1。**朱は大きな文字（18pt以上）とグラフィックにのみ使い、本文サイズの文字には使わない。**

### 5.2 書体

| 役割 | 書体 | ウェイト |
|---|---|---|
| 本文・UI | BIZ UDPGothic | 400 / 700 |
| 出席番号・数値 | BIZ UDGothic（等幅） | 700 |
| 見出し（少量） | Klee One | 600 |

BIZ UD系は日本の学校・自治体の配布物で実際に使われるユニバーサルデザイン書体で、朝の逆光の教室で読める。等幅版を数値に使うことで34個の番号が桁で揃う。Klee Oneは教科書体系の手書き感を持ち、画面名とラベルにのみ使う（**本文には使わない**）。

`@fontsource-variable/*` / `@fontsource/*` でバンドルする。Fontsourceの日本語フォントはunicode-rangeで分割されており、必要なサブセットのみ読み込まれる。

### 5.3 主画面の原則

主画面から説明文をほぼ排除し、番号とセルの状態だけで情報を伝える。腕を伸ばした距離から読めるサイズ（セル最小64px、番号24pt以上）を確保する。

### 5.4 品質の下限

- スマホ幅（375px）まで崩れないこと
- キーボードフォーカスが視認できること
- `prefers-reduced-motion` を尊重すること

## 6. バリデーションとエラー処理

| 状況 | 挙動 |
|---|---|
| 出席番号が重複 | 保存前に検証し、「出席番号12はすでに使われています」と入力欄の下に表示。転出者との重複なら「12番は転出した生徒の欠番です」と理由を示す |
| 出席番号が0以下または非数値 | 「出席番号は1以上の数字で入力してください」 |
| クラス名が空 | 「クラス名を入力してください」 |
| IndexedDBが使用不可 | 全画面でエラー表示。「この端末ではデータを保存できません。プライベートブラウズを解除して開き直してください」 |
| QR生成失敗 | 該当カードの位置に「QRを生成できませんでした」と出席番号を表示し、他のカードの印刷は続行する |

エラー文は何が起きたかと次にどうするかを示す。謝らない。

## 7. テスト方針

TDDで進める。実装前にテストを書く。

**データ層**（`fake-indexeddb` 使用）
- cohortの作成と `isActive` が1件のみに保たれること
- 生徒の追加時に出席番号が正しく自動採番されること（転出者を含む最大値+1）
- 出席番号の重複が拒否されること（在籍・転出の両方に対して）
- 転出で番号が欠番として維持されること
- 物理削除で番号が再利用可能になること

**コンポーネント**
- cohortが無いとき `/setup` にリダイレクトされること
- 名簿グリッドが在籍・欠番を正しく描き分けること
- `showStudentNames` のOFFで氏名が名簿・印刷シートの両方から消えること
- 印刷シートが在籍者のみを、12枚/ページで並べること

**QRペイロード**
- 生成される文字列が `hw1:<uuid>` 形式であること
- 出席番号を変更してもペイロードが変わらないこと

## 8. 決定事項の要約

1. QRには内部ID（uuid）を埋め込む。出席番号ではない。
2. 転出はデフォルトで番号を欠番として維持する。物理削除も明示的に選べる。
3. 印刷はブラウザの印刷機能のみ。PDF生成は行わない。
4. データモデルは年度＋クラス（cohort）単位で最初から定義する。
5. フォントはセルフホストする。オフライン要件をステップ1から満たすため。
