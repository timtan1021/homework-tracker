# 先生画面の見直し: 提出チェック表・採点タブ・山吹

## 解きたいこと

実機で使い始めた先生から、次の3つが出た。

1. **未提出者一覧**が読めない。番号のグリッドだけで誰か分からない。未提出の人しか出ないので「全員がどうなっているか」が見えない。「あと何人」「何割」が数字で出ない
2. **採点画面**が長い。34人×提出物で行が縦に伸び、1行に3つボタンが並んで見づらい。「未採点」と「再提出待ち」が上下に積まれていて境目が弱い。誰の分か、あと何件かがすぐ見えない
3. 全体に**シンプルで使いやすいが、やる気が出ない**。配色も見直したい

CLAUDE.mdの前提(片手でタブレット、読む時間はない、44px、24pt、5色)は崩さない。増やすのは色を1つと、達成が見える形だけ。

## 決めたこと

### 6色目「山吹」を足す。用途は「提出済み・達成・進捗」に限る

- `--color-yamabuki: #e39b12`(面として使う)と `--color-yamabuki-usu: #fbeccb`(提出済みセルの地)の2値を追加する
- **山吹を文字色にしない。** 画用紙の上に山吹の文字を置くとコントラスト比が約2.4:1で読めない。山吹は必ず「面」で、その上の文字は墨(コントラスト比 約8.6:1)
- 藍は今まで通り「操作」の色(ボタン、リンク、選択中)。山吹は「できた」の色。役割を混ぜない
- **朱の扱いは変えない。** 花丸と、完全に元へ戻せない操作の確認ダイアログだけ
- 花丸は「提出した」の記号のまま。先生側の達成(全員提出、採点完了)には花丸を使わず、山吹の帯と文字で示す。モックアップでは帯に花丸を添えたが、記号の意味を1つに保つため採用しない
- CLAUDE.mdの「配色は5トークンのみ」を「6トークン」に改め、山吹の用途限定を書き足す

配色を選ぶために3案(藍のみ / 山吹 / 若葉)をモックアップで並べ、山吹を選んだ。理由: 藍と補色に近く少ない面積で目立つこと、朱(線)と山吹(面)で役割が被らないこと。

### 未提出者一覧を「提出チェック表」にする

縦に在籍生徒、横にその日の提出物。全員の状態が1画面で分かる形。

- **上部**: その日の提出物ごとに進捗バー(山吹)と「28/34」。全員提出した提出物はバーが満ち、数字の代わりに「全員」と出る。さらにその上に「計算ドリル 全員提出」の帯(山吹の地、墨の文字)を出す
- **表**: 行 = 在籍生徒(出席番号を24pt以上で。設定「氏名を表示する」がONなら氏名も)。列 = その日が提出日の提出物(曜日繰り返し・日付指定の両方)。列見出しに提出物名と「28/34」、その下に締切前なら「あと◯分」、過ぎていれば「確定」(現行の表示を移す)
- **セル**: 提出済み = 淡山吹の地に墨の「✓」。未提出 = 方眼の枠だけ。欠席 = 斜線ハッチに「欠」(現行の欠席セルと同じ見た目)
- **セルの操作**: 未提出セルをタップ → 「◯番を欠席にしますか」(現行の確認ダイアログ、藍)。欠席セルをタップ → 取り消しの確認。提出済みセルはタップしても何も起きない(取り消しはスキャン画面と採点画面の役割。この画面に削除を持ち込まない)
- **横幅の式**: 375px幅の内寸は343px。生徒列96px + 提出物列(44px + 間隔8px)×N。N=3で252px、N=4で304px、N=5で356px。**5列以上は表の入れ物だけ横スクロール**にし、生徒列は`position: sticky; left: 0`で残す。ページ本体は横に動かさない
- **下部**: 「直近2週間で未提出が多い生徒」は残す。氏名は設定に従う(現行通り)
- **日付送り**、ヘッダー、読み込み中の外枠保持(Grading.tsxと同じ理由)は現行通り

### 採点画面をタブにする

- 「未採点」「再提出待ち」を上下に積むのをやめ、画面上部の**2つのタブ**にする。`role="tablist"`/`role="tab"`/`aria-selected`を付け、選択中は藍の塗り。タブ名に件数バッジ(山吹の地、墨の文字)。未採点の件数は今見ている日の件数(受け取った日で絞る現行の仕様を維持)。再提出待ちの件数は日付に依らない総数
- 「ほかの日に未採点◯件 → 一番古い日へ」は未採点タブの中に残す
- **提出物ごとの見出し**に「あと◯件」(未採点タブ)、「◯人」(再提出待ちタブ)
- **行**: 出席番号を大きく、設定ONなら氏名、遅れて提出・先に提出のラベルは現行通り
- **ボタン(未採点タブ)**: 「合格」(山吹の面、墨の文字) / 「再提出」(藍の輪郭) の2つに絞る。3つ目の「提出を取り消す」は行の端の「⋯」ボタン(44px四方)に収め、押すと行の直下に「提出を取り消す」が展開する。押すと現行通り朱の確認ダイアログ
- **ボタン(再提出待ちタブ)**: 「合格」 / 「未採点に戻す」(下線)。現行通り。取り消しは置かない
- 未採点タブが0件なら「未採点はありません」を山吹の帯で出す(達成の表示)。再提出待ちが0件なら「再提出待ちの生徒はいません」(通常の文)
- タブの選択状態は画面内の状態(URLは`/grading`のまま)。日付を送ってもタブは保つ

### 変更しないもの

- DBのストア・インデックス・`DB_VERSION`。読み取りモデルを足すだけで、書き込み経路は変えない
- スキャン画面・児童用スキャン画面の構造。花丸は朱のまま。児童向けの演出は別の設計にする
- 名簿画面。「提出物の設定」は残す(曜日で繰り返す宿題を使っている)
- 欠席マークの確認ダイアログの有無(1人ずつ確認する現行の運用)

## 実装

### 配色トークン(`src/styles/index.css`, `CLAUDE.md`)

`@theme`に`--color-yamabuki`と`--color-yamabuki-usu`を足す。CLAUDE.mdの「譲れない制約」を改める。

### 提出チェック表の読み取りモデル(`src/db/dailyRoster.ts`, `src/hooks/useDailyRoster.ts`)

```ts
export type CellState = "submitted" | "absent" | "none";
export type DailyRoster = {
  types: { type: SubmissionType; deadlinePassed: boolean; submittedCount: number }[];
  rows: { student: Student; cells: Record<string, CellState> }[]; // key = type.id
  activeCount: number;
};
export function listDailyRoster(cohortId: string, date: string, now: Date): Promise<DailyRoster>;
```

`listStudents`・`listSubmissionTypes`・`listSubmissions`を1回ずつ読み、在籍生徒×その日が提出日の提出物で埋める。`status`の無い旧レコードは提出済み扱い(既存と同じ後方互換)。`listTodayNonSubmitters`(`src/db/nonSubmitters.ts`)はこの画面からしか使われていないので、置き換えたら関数とテストを消す。`countRecentNonSubmissions`は残す。

### 提出チェック表(`src/screens/Unsubmitted.tsx`, `src/components/CheckTable.tsx`, `src/components/ProgressBar.tsx`)

- `ProgressBar`: `value`/`max`を受け、山吹の塗りと「28/34」または「全員」を出す。`role="progressbar"`と`aria-valuenow`等を付ける
- `CheckTable`: `DailyRoster`と`showNames`を受けて表を描く。セルは`<button>`(未提出・欠席)または装飾なしの`<span>`(提出済み)。セルの`aria-label`は「12番 計算ドリル 提出済み」の形
- `Unsubmitted.tsx`は`useDailyRoster`に差し替え、`pending`(欠席にする/取り消す)と確認ダイアログは現行のまま流用する。URL・画面名は変えない(名簿からの導線「未提出者・集計を見る」の文言はそのまま)

### 採点画面(`src/screens/Grading.tsx`)

- `tab: "ungraded" | "resubmit"`の状態を足し、タブの見出しに`data.ungraded.length`と`data.resubmitPending.length`を出す
- `GradingRow`から3つ目のボタンを外し、`onWithdraw`がある行に「⋯」ボタンと展開領域を足す。展開の開閉は行ごとの状態(`openMenuId`)で1行だけ開く
- 「合格」の配色を`bg-yamabuki text-sumi`にする。「再提出」「未採点に戻す」は現行通り

### 確認手順(`docs/手元での確認手順.md`)

提出チェック表(横スクロール・sticky列・セルの操作)、採点タブ(件数・⋯メニュー)、山吹の見え方(教室の明るさで山吹の上の墨が読めるか)を追記する。

## テスト

- `dailyRoster.test.ts`: 在籍生徒だけが行に出る / その日が提出日でない提出物は列に出ない / 提出済み・欠席・未記録が正しいセル状態になる / `status`の無い旧レコードは提出済み / 人数の集計
- `Unsubmitted.test.tsx`: 全員の行が出る / 列見出しの人数 / 全員提出の帯 / 未提出セルのタップで欠席の確認が出る / 欠席セルのタップで取り消しの確認が出る / 提出済みセルは押せない / 氏名は設定に従う / 日付送りで表が差し替わる。既存の「締切前は残り時間」「確定」のテストは列見出しの検証に移す
- `Grading.test.tsx`: タブの切り替えと`aria-selected` / タブの件数 / 見出しの「あと◯件」 / 「⋯」を押すと「提出を取り消す」が出る / 別の行の「⋯」を押すと前の展開が閉じる / 未採点0件で帯が出る。既存の合格・再提出・未採点に戻す・取り消しのテストは維持する(取り消しは「⋯」経由に書き換える)
- `ProgressBar.test.tsx`: 値と最大値の表示 / 全員のときの表記 / `aria-valuenow`
- 各タスクで、実装前にテストが落ちることを確認する(わざと壊す)

## 実装後の機械的な検査

- 朱: `grep -rn "shu" src --include=*.tsx` が `Hanamaru.tsx`と`ConfirmDialog.tsx`(tone="danger")だけであること
- 山吹の文字色: `grep -rn "text-yamabuki" src` が0件であること
- Tailwind素のカラー・`any`: 現行の検査と同じ
- タップ領域: 新しいボタン(セル、タブ、⋯)がすべて`min-h-11`または`size-11`を持つこと
- 375px: `CheckTable`の列数と幅の式をコメントに書き、テストで`index.css`との二重管理が無いことを確認する(寸法はコンポーネント内の定数だけに置く)
