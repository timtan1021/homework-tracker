# 宿題提出管理アプリ — ステップ6「PWA化・HTTPS配信」設計書

作成日: 2026-08-24

## 1. 背景とスコープ

ステップ1〜3で名簿・QRカード印刷・提出物マスタ・スキャン画面が完成している。本設計書は**ステップ6「PWA化・HTTPS配信」のみ**を対象とする。

ステップ6の完了条件は、**先生がホーム画面のアイコンから開き、電波の無い教室でも起動して使える状態**になること。

### なぜ順番を入れ替えるか

仕様書ではステップ4（未提出者一覧・集計）、5（バックアップ）の後にPWA化を置いていた。これを先に行う。

- **カメラは HTTPS でしか動かない。** ステップ3のスキャン機能は、この配信が済むまで実機で一度も試せない
- 印刷・花丸・375px幅のレイアウトなど、**3ステップ分の未確認項目が溜まっている**。実機で開けるようになれば、まとめて確認できる
- 実使用の感触をステップ4以降の設計に反映できる

### スコープ外
- 未提出者一覧・履歴集計・自動未提出確定（ステップ4）
- JSON/CSVエクスポート・インポート（ステップ5）

## 2. フォントのプリキャッシュ（本ステップ最大の論点）

### 測定結果

素朴に全部プリキャッシュすると、ビルド出力は **25MB**（うち woff2 が 11.5MB、CSS が 504KB）になる。教室のWi-Fiで初回に落とす量として現実的ではない。

| 書体 | 全サブセット | サブセット数 | 用途 |
|---|---|---|---|
| BIZ UDPGothic | 5.45MB | 244 | 本文すべて、生徒氏名 |
| BIZ UDGothic | 2.77MB | 122 | 数字・時刻のみ |
| Klee One | 3.32MB | 122 | 見出しのみ |

Fontsource の日本語フォントは `unicode-range` で細かく分割されており、`@font-face` 宣言が496個ある。**ブラウザは実際に表示する文字を含むサブセットしか取りに行かない。**

その効きが最も大きいのが `BIZ UDGothic` である。`font-num` として**数字と時刻にしか使っていない**ため、実際に取得されるのは数字を含む1サブセット（16.7KB）だけで、残り121サブセットは一度も使われない。2.77MB のうち取得されるのは 16.7KB である。

この性質を利用する。

### 方針

**プリキャッシュはフォント実体を含めない。**

| 対象 | 量 | 扱い |
|---|---|---|
| JS | 417KB | プリキャッシュ |
| CSS（496個の `@font-face` 宣言を含む） | 503KB | プリキャッシュ |
| HTML | 1KB未満 | プリキャッシュ |
| woff2（フォント実体） | 11.54MB | **実行時キャッシュ（`CacheFirst`）** |

**初回に落ちるのは約920KB。** フォントは表示に使われた文字のサブセットだけが、その場でネットワークから取られ、以後は端末に残る。

CSSに496個の `@font-face` 宣言が入っているが、ブラウザは**実際に使う文字を含むサブセットしか取りに行かない**。日本語UIを1画面出したときに取られるのは数十KB程度で、11.54MBが一度に落ちることはない。

### 自動判定はしない

「UI文言に出る文字を走査して、必要なサブセットだけをプリキャッシュ対象に加える」ことは技術的には可能だが、採用しない。文言を1つ足すたびに判定が古くなり、**気づかないまま字が出なくなる**。壊れ方が静かすぎる。

ブラウザのサブセット選択に任せるほうが、仕組みとして単純で壊れにくい。

### この方針が受け入れる制約

**初回はオンラインで開く必要がある。** ホーム画面に追加する操作自体がオンラインで行われるため、実運用と矛盾しない。

**電波の無い教室で、まだ一度も表示していない文字は出ない。** 具体的には次の場合。

- 氏名表示をONにした先生が、登録済みの生徒を初めてオフラインで表示する
- 新しいクラス名に、それまで使っていない漢字が含まれる

いずれも**出席番号は表示されるため機能は失われない**。氏名表示は既定でOFF（ステップ1の決定）であり、生徒の登録は職員室など電波のある場所で行われる想定。

全サブセットをプリキャッシュすれば完全にオフライン化できるが、初回に12MBを要求することになる。教室で使う道具として、**920KBで起動して一部の字が出ないことより、12MBを落とせず起動しないことのほうが重い。**

## 3. 配信

Cloudflare Pages / Netlify のどちらでも動く形にする。特定サービスに依存する設定は入れない。

- ビルド出力は `dist/`。`base` はルート（`/`）
- `public/_redirects` に `/* /index.html 200` を置く。**この1ファイルで Cloudflare Pages と Netlify の両方に効く**
- `BrowserRouter` を維持する。URLに `#` が入らない

ステップ1の最終レビューで「静的ホストでのページ再読み込みが404になる」と指摘された問題が、ここで解消する。

## 4. Service Worker

`vite-plugin-pwa`（1.3.0）の `generateSW` を使う。Workbox を自前で組むより設定が小さい。

**外部と通信しないアプリなので、API向けの実行時戦略は不要。** 必要なのはフォントの `CacheFirst` だけである。

```
registerType: "prompt"
```

自動更新にしない理由は次項。

## 5. 更新の知らせ方

新しい版を検知したら、画面下部に藍の帯を出す。

```
┌─────────────────────────────┐
│   （通常の画面）              │
│ ─────────────────────────── │
│ 新しい版があります  ［更新］  │
└─────────────────────────────┘
```

- **勝手に再読み込みしない。** スキャン中に画面が切り替わると、記録できたのか分からなくなる
- 「更新」を押したときだけ `skipWaiting` して再読み込みする
- 無視しても使い続けられる。帯は次に開いたときまた出る

## 6. manifest とアイコン

```json
{
  "name": "宿題提出管理",
  "short_name": "宿題チェック",
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#FBFAF7",
  "theme_color": "#22406B",
  "lang": "ja",
  "start_url": "/"
}
```

**アイコンは花丸。** 藍地（`#22406B`）に朱（`#D8452E`）の花丸を描く。既存の `Hanamaru` と同じ線を使うため、アプリを開く前から同じ記号が目に入る。

必要なサイズ: 192×192、512×512、maskable 512×512、apple-touch-icon 180×180。

**生成はビルド時に行わない。** 一度だけ実行するスクリプト（`scripts/generate-icons.mjs`）で `sharp` を使ってSVGからPNGを作り、結果を `public/` にコミットする。アイコンは滅多に変わらないため、毎ビルド生成する必要がない。

## 7. ホームを `/scan` にする

catch-all（`*`）の行き先を `/roster` から `/scan` に変える。毎朝の動線が1タップ短くなる。

**分岐は入れない。** 提出物が未登録のときスキャン画面は既に「まず提出物を登録してください」と設定への導線を出すため、行き止まりにならない。cohort が無ければ `CohortGate` が `/setup` へ送る。分岐を足すと挙動が読みにくくなる。

初回セットアップ後の遷移（`Setup` → `/roster`）は変えない。クラスを作った直後にすることは生徒の登録である。

## 8. standalone での行き止まり

ホーム画面から開くとブラウザの戻るボタンが無くなる。ステップ1の最終レビューで指摘され、全画面エラーには「名簿に戻る」を置き済みだが、通しで確認する。

## 9. テスト方針

**Service Worker は jsdom で動かない。** テストできるのは以下に限られる。

- `manifest` の内容（必要なサイズのアイコンが揃っているか、`display` が `standalone` か等）
- 更新通知の表示・非表示のロジック（Service Worker の登録部分をモックする）
- catch-all の行き先が `/scan` になったこと
- 既存の全テストが壊れていないこと

**オフライン起動、キャッシュの実効、ホーム画面への追加は実機でしか確かめられない。** 確認手順に記す。

## 10. 決定事項の要約

1. プリキャッシュはフォント実体を含めない。初回約920KB。フォントは実行時キャッシュに委ね、初回はオンラインで開く前提を置く
2. `BIZ UDGothic` は数字専用なので、実際に取得されるのは1サブセット（16.7KB）だけ。全122サブセットのうち121は一度も使われない
3. `_redirects` 1ファイルで Cloudflare Pages と Netlify の両方に対応する
4. 更新は知らせてから切り替える。勝手に再読み込みしない
5. アイコンは花丸。生成は一度だけのスクリプトで行い結果をコミットする
6. ホームを `/scan` にする。分岐は入れない
