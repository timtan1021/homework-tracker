# 手元での確認手順

実装中、ブラウザを開ける環境がなかったため、**画面の見た目と印刷結果は一度も実物で確認されていません**。テストと計算では守れる範囲を守りましたが、以下は人の目でしか確かめられません。

## まず配信する（これが済むとタブレットで試せます）

`npm run dev` はPCのブラウザでしか使えません。**タブレットで試すには一度配信が必要です。** カメラはHTTPSでしか動かないためです。

```
npm install    # 初回のみ
npm run build
```

`dist` フォルダができます。次のどちらかにドラッグ＆ドロップしてください。どちらも無料でHTTPSが付き、アカウントの用意だけで済みます。

- **Netlify**: https://app.netlify.com/drop を開いて `dist` を放り込む
- **Cloudflare Pages**: ダッシュボード → Workers & Pages → Create → Pages → Upload assets

発行されたURLをタブレットで開き、ブラウザのメニューから「ホーム画面に追加」します。

配信せずPCだけで確認する場合は `npm run dev` で `http://localhost:5173` を開いてください（localhost はカメラが使える例外です）。

## 1. 最優先 — 印刷が3枚に収まるか

**これが今回いちばん確認が必要な項目です。** 一度A4の印字領域を7.3mm超過する不具合が出ており、修正しましたが実物での確認ができていません。

1. クラスを作る（年度・クラス名）
2. 生徒を34人登録する。「保存して続けて追加」を押し続けると番号が自動で進みます
3. 「QRを印刷」を開く
4. ブラウザの印刷プレビューを開く（Macなら `⌘P`）

**確認すること:**

- [ ] ちょうど **3枚** になっている（4枚以上なら、はみ出しが直っていません）
- [ ] 1枚目と2枚目が **12枚ずつ**、3枚目が **10枚**
- [ ] 最終行が次の用紙に押し出されていない
- [ ] カードの裁ち線（破線）が見える
- [ ] 各ページ上部の「2026年度 5年1組」が読める

用紙サイズは **A4縦**、余白は「デフォルト」または「なし」を選んでください。ブラウザ側で余白を追加すると計算が狂います。

## 2. 実物のQRが読めるか

1. 1枚だけ印刷する
2. カードを1枚切り出す
3. **ラミネートする**（反射の影響を見るため、ラミネート後に試すことが重要です）
4. スマホのカメラアプリで読む

**確認すること:**

- [ ] `hw1:` で始まる文字列が読み取れる
- [ ] 少し斜めから、また教室の照明下でも読める

読めない場合は教えてください。誤り訂正レベルは上げてありますが、QRの寸法（現在38mm）を大きくする余地があります。

## 3. 通しで動くか

- [ ] 初回起動でクラス作成画面が出る
- [ ] 生徒を追加できる。番号が自動で次に進む
- [ ] 名簿の番号をタップすると編集画面に入る
- [ ] 1人を「転出にする」→ 名簿でその番号が破線＋斜線になり、「在籍33人・欠番1」になる
- [ ] 転出した生徒のカードが印刷に含まれない
- [ ] 設定で「氏名を表示する」をONにすると、名簿と印刷の両方に氏名が出る
- [ ] **オフラインにして再読み込みしてもデータが残っている**（機内モードにしてリロード）

## 4. 見た目

タブレットとスマホの両方で、できれば朝の教室の明るさで見てください。

- [ ] スマホ幅で名簿が4列に収まり、横スクロールが出ない
- [ ] **出席番号が腕を伸ばした距離から読める**（この画面の存在理由です。小さければ言ってください）
- [ ] 転出（欠番）が一目で在籍と区別できる
- [ ] 書体が意図どおり出ている（見出しは手書き風のKlee One、番号は等幅のBIZ UDGothic）
- [ ] キーボードのTabで操作したとき、どこにフォーカスがあるか見える

## 5. 削除の確認ダイアログ

- [ ] 「完全に削除」を押すとダイアログが出て、赤（朱色）で警告される
- [ ] Tabキーを何度押してもダイアログの中の2つのボタンを往復し、背面に抜けない
- [ ] Escapeキーで閉じる
- [ ] 「転出」と「完全に削除」の違いが画面の説明で分かる

# ステップ2（提出物マスタ）の確認

## 6. 最優先 — 既存の名簿が消えていないか

**すでにアプリを開いてクラスや生徒を登録したことがある場合、これを最初に確認してください。**

ステップ2でデータベースの構造を変更しました。移行を間違えると名簿が失われますが、まだバックアップ機能がありません（ステップ5）。テストでは守っていますが、実機での確認は別です。

- [ ] アプリを開き、**登録済みのクラスと生徒がそのまま残っている**
- [ ] 出席番号、氏名、転出の状態も変わっていない

もし消えていたら、それ以上操作せずすぐ教えてください。

## 7. 提出物の登録

1. 名簿の下部にある「提出物の設定」を開く
2. 「提出物を追加」で登録する

- [ ] 名簿の下部ボタンが2行になっている（1行目に「生徒を追加」、2行目に「QRを印刷」「提出物の設定」）
- [ ] **曜日の7つのボタンがスマホ幅で1行に収まる**（計算上は332px、画面の内寸343pxに対し余裕11px）
- [ ] 曜日ボタンが押しやすい大きさ（44px四方）
- [ ] 締切時刻をタップすると、OS標準の時刻ピッカーが出る
- [ ] 選択中の曜日が一目で分かる（藍の塗り）

## 8. 提出物の運用

- [ ] 「計算ドリル」「音読カード」「日記」を登録し、一覧に締切と曜日が出る
- [ ] すべての曜日を選ぶと「毎日」と表示される
- [ ] 「↑」「↓」で並べ替えられ、先頭の「↑」と末尾の「↓」は押せない
- [ ] 1つを「終了にする」と、破線＋斜線になり末尾に移動し、並べ替えボタンが消える
- [ ] 終了したものと同じ名前で新規登録しようとすると、理由付きで止められる
- [ ] 「完全に削除」は赤い確認ダイアログが出る

## 9. まとめて

- [ ] 名簿と提出物の画面を行き来しても迷わない（見出しの書き方、件数の表記が揃っている）
- [ ] オフラインにして再読み込みしても、提出物の設定が残っている

# ステップ3（スキャン画面）の確認

## 10. 最優先 — 既存データが消えていないか

ステップ3でもデータベースの構造を変更しました（バージョン3）。

- [ ] クラス・生徒・提出物がすべて残っている

消えていたら、それ以上操作せずすぐ教えてください。

## 11. カメラが使える条件（重要）

**カメラは HTTPS でしか動きません。** ブラウザの制約で、ポリフィルも回避策もありません。

- `npm run dev` の `http://localhost:5173` → **動きます**（localhost は例外扱い）
- `npm run dev --host` の `http://192.168.x.x:5173` → **動きません**

スマホやタブレットで試すには、同じ端末で localhost を開くか、ステップ6のHTTPS配信を待つ必要があります。まずはPCのブラウザで確認してください。

- [ ] `http://localhost:5173` を開き、名簿から「提出チェック」に入る
- [ ] カメラの許可を求められ、許可すると映像が出る
- [ ] **許可を拒否すると、自動的に番号モードに切り替わり理由が出る**

## 12. 番号でチェックする

カメラが使えなくても、この経路だけで宿題チェックが完結します。

- [ ] 「番号でチェック」に切り替えると出席番号が並ぶ
- [ ] 転出した生徒は出ない
- [ ] 番号をタップすると**花丸が描かれ**「12番 提出しました」と出る
- [ ] 花丸が円→花弁の順に描かれる（一瞬で出るのではなく、ペンで描く感じ）
- [ ] 同じ番号をもう一度タップすると「提出済み」になり、花丸は出ない
- [ ] 提出済みの番号のセルに小さく花丸が付く
- [ ] 下部の進捗（「計算ドリル 8人」）が増える

## 13. 提出物の選択

- [ ] その日の曜日に合う提出物だけが並ぶ（月曜に「日曜のみ」の提出物は出ない）
- [ ] 最初は全部選ばれている
- [ ] タップで外せる。全部外すと「チェックする提出物を選んでください」と出て記録できない
- [ ] 複数選んだ状態で1回タップすると、選んだ全部が記録される

## 14. カメラでのスキャン（HTTPSまたはlocalhostで）

ステップ1で印刷・ラミネートしたQRカードを使います。

- [ ] カードをかざすと読み取れて花丸が出る
- [ ] **同じカードをかざし続けても、結果表示が点滅しない**（2秒間は読み直さない設計）
- [ ] 商品のバーコードなど別のQRをかざしても何も起きない
- [ ] 転出した生徒のカードでは「転出しています」と出る

## 15. 動きを減らす設定

OSで「視差効果を減らす」等を有効にしてから開いてください。

- [ ] 花丸がアニメーションせず、完成形で即座に表示される（描画途中で消えない）

# ステップ5（バックアップ・復元）の確認

## 16. 書き出し

1. 名簿から「設定」を開く
2. 「バックアップを書き出す」を押す

- [ ] ファイルが実際にダウンロードされる
- [ ] ファイル名が `宿題管理_バックアップ_YYYYMMDD.json` になっている
- [ ] ダウンロードしたファイルをテキストエディタで開き、日本語が文字化けしていない

## 17. 設定画面からの復元

- [ ] バックアップファイルを選ぶと、朱色の確認ダイアログが出る
- [ ] 「やめる」を押すと何も変わらない
- [ ] 「復元する」を押すと、選んだファイルの内容に置き換わる
- [ ] 壊れたファイル（拡張子だけ`.json`にしたテキストファイル等）を選ぶとエラーが出る

## 18. 機種変更を想定した復元（最も重要）

**これが復元機能の本来の使い方です。**

1. 別の端末（またはブラウザのプライベートウィンドウ）でアプリを開く
2. まだクラスが無い状態（初回セットアップ画面）で、書き出しておいたファイルを選ぶ

- [ ] 確認ダイアログを経ずに、そのまま名簿へ進む
- [ ] 元の端末と同じ生徒・提出物・提出記録が入っている

# ステップ4（未提出者一覧・集計）の確認

締切前後どちらの場面でも使う画面です。可能なら実際の締切時刻をまたいで、同じ画面が変わる様子を見てください。

## 19. 名簿からの導線

1. 名簿の下部にある「未提出者・集計を見る」を開く

- [ ] 名簿の下部ボタンが3行になっている（1行目「生徒を追加」、2行目「QRを印刷」「提出物の設定」、3行目「未提出者・集計を見る」）
- [ ] 開くと、今日の日付が見出しに出る

## 20. 締切前後の表示

1. 締切前の提出物を1つ登録し、生徒を数人未提出のままにしておく

- [ ] 締切前は「あと◯分」と藍色の枠で出る（朱色ではない）
- [ ] 締切を過ぎると同じ生徒の一覧が「確定」（墨地に白抜き）に変わる
- [ ] 全員提出し終えると、番号のグリッドが消えて「◯◯は全員提出しました」に変わる
- [ ] 今日が提出日でない提出物（曜日設定外）は一覧に出ない
- [ ] 転出した生徒は未提出として出ない

## 21. 直近2週間の集計

- [ ] 何日か使ったあと、未提出が多い生徒が上位に出る
- [ ] 一度も未提出が無い生徒は集計に出ない
- [ ] 集計対象の提出物を「終了にする」と、その提出物ぶんの未提出は集計から消える

## 22. 見た目・オフライン

- [ ] スマホ幅で番号のグリッドが名簿と同じ大きさで読める
- [ ] 欠席にマークしたセルの番号が、腕を伸ばした距離から読める（薄い色のため確認が必要）
- [ ] オフラインにして再読み込みしても表示される

## 22.5 欠席マークの操作

- [ ] 未提出のセルをタップすると「◯番を欠席にしますか」の確認が出る（朱色ではなく藍色）
- [ ] 「欠席にする」を押すと、そのセルだけ見た目が変わる（破線・薄い色）
- [ ] 欠席にしたセルをもう一度タップすると「取り消しますか」の確認が出て、取り消すと元の未提出セルに戻る
- [ ] 「やめる」を押すと何も変わらない
- [ ] 欠席にした生徒は、直近2週間の集計から消える（未提出回数に数えられない）
- [ ] 書き込みに失敗させる状況を作れなくても構わないが、通信の悪い環境で試して何かしらエラーが出た場合は、その文言をそのまま教えてください

# ステップ7（日付指定の宿題・カレンダー画面）の確認

カレンダー画面から一回きりの宿題を登録する機能です。入力欄の確定はタップ外し(blur)で行い、新しい入力欄は開いた時点でキーボードが自動で開く想定ですが、どちらも実ブラウザでのタップ・フォーカスの挙動に依存するため自動テスト(jsdom)では確認できません。iOS Safariで確かめてください。

## 23. iOS Safariでの入力

- [ ] 入力欄の外を1回タップしただけで確定し、宿題名が反映される（キーボードを閉じるだけで終わり、確定していない、ということがない）
- [ ] 「タップして登録」「＋もう1件」を押して入力欄を開いたとき、その場でソフトウェアキーボードが自動で開く

## 24. 削除の確認と前週・次週の移動

- [ ] 登録済みの宿題の「削除」を押すと、朱色の確認ダイアログが出て「記録済みの提出情報も含めて、元に戻せません」と表示される（曜日繰り返しの提出物の完全削除と同じ見た目）
- [ ] 「削除する」を押すと一覧から消える。「やめる」を押すと何も変わらない
- [ ] 次週・前週で表示が切り替わり、別の週に登録した宿題が正しく出る
- [ ] 未確定の入力欄やエラーが表示された状態で週を移動しても、戻ってきたときに再現しない（何も操作していないのに入力欄やエラーが勝手に開かない）

## 児童用ページと教員用ページの分離

- [ ] 初期設定（クラス作成とパスワード設定）を終えるまで端末を子供に渡さない。
      パスワードを決めるまでは、誰でも設定画面にたどり着ける
- [ ] 合言葉を紙に控えて保管する。控えないまま画面を閉じると二度と表示できない
- [ ] 児童画面の「せんせい」を押すと、名簿ではなくパスワード入力が出る
- [ ] 教員画面から「児童画面に戻る」を押したあと、ブラウザの戻るボタンで
      名簿に戻れない
- [ ] アプリを再起動すると、もう一度パスワードを求められる
- [ ] 提出物を選ばずにQRをかざしても、花丸が出ず記録もされない
- [ ] 1人スキャンしたあと、提出物の選択が外れている（次の子が選び直す）
- [ ] 児童が実際にかざす高さ・距離でカメラが読み取れる。
      教室に据え置く場合、先生が手に持つ場合と画角の条件が変わる
- [ ] 375px幅の端末で児童画面が崩れない
- [ ] パスワードを忘れた状態から、合言葉だけで復旧できる（通しで一度やる）
